# SEO-004 可访问性基线与 WCAG 2.2 AA 缺口表

> 基线日期：2026-07-30  
> 状态：自动化与键盘/reflow 基线通过；真实 Narrator 语音检查待重试，Gate 3 尚未关闭

## 1. 范围与工具

本基线只覆盖当前已经实现且可验收的模板，不把未来消息、支付或视频页面伪装成已检查：

- 中文首页；
- 英文 Rental 列表/筛选和详情；
- 英文 Rental 发布表单的初始与校验错误状态；
- 私有账户 guest 边界；
- Admin 登录边界。

自动化在真实 production standalone Web/Admin 上运行，使用 Playwright 1.61.1 的 Desktop Chrome 与
Pixel 7 项目，以及固定 `@axe-core/playwright`/axe-core 4.12.1。扫描标签为 `wcag2a`、`wcag2aa`、
`wcag21a`、`wcag21aa`、`wcag22aa`。命令：

```bash
pnpm test:a11y
pnpm test:a11y:ci
```

axe 只能发现部分机器可判定问题，不能替代键盘、缩放、屏幕阅读器、认知负担或内容质量判断。

## 2. 当前证据

| 检查             | 环境/方法                                                      | 结果                                                             | 状态   |
| ---------------- | -------------------------------------------------------------- | ---------------------------------------------------------------- | ------ |
| axe WCAG 2.2 AA  | 5 类模板，Desktop Chrome + Pixel 7                             | 8/8 production browser cases；0 violation                        | 通过   |
| 跳过链接         | 首次 Tab、可见焦点、Enter 到 `main`                            | 中英文统一链接；目标获得焦点和可见轮廓                           | 通过   |
| 键盘焦点         | 原生控件与链接、forced-colors                                  | 默认/强制颜色下焦点可见                                          | 通过   |
| 表单错误         | 空 Rental 保存                                                 | alert 摘要、字段 `aria-invalid`/`aria-describedby`、焦点移到首错 | 通过   |
| 目标尺寸         | 表单错误摘要链接                                               | 每个可操作目标至少 24 CSS px                                     | 通过   |
| reflow           | 320 CSS px（1280 宽页面 400% 或 640 宽页面 200% 的更严格宽度） | 无横向页面滚动；axe 仍为 0                                       | 通过   |
| reduced motion   | `prefers-reduced-motion: reduce`                               | 动画/过渡缩至 0.01ms，平滑滚动关闭                               | 通过   |
| 私有/Admin       | guest 账户与 Admin 登录                                        | axe 0；移动无横向页面滚动                                        | 通过   |
| Windows Narrator | 独立 Edge + Narrator 计划检查标题、地标、搜索、错误播报        | Windows 自动化因不能高置信识别浏览器 URL 而安全停止；未施加输入  | 待重试 |

首轮扫描确实发现并修复了问题，而不是先写“通过”：主页/发布表单的低对比度文字和按钮、移动端隐藏
搜索文字后的无名称按钮、只有部分公开模板具备跳过链接、错误摘要链接不足 24px。颜色令牌现在至少满足
普通文本 4.5:1；所有当前 Web `<main>` 都有唯一可聚焦跳转目标。
