# ADR-0001：首期采用模块化单体

- 状态：Accepted
- 日期：2026-07-21
- 决策者：项目架构基线

## 背景

产品包含身份、分类信息、搜索、消息、审核、商家、支付和广告等多个领域，但团队、流量和边界尚未通过生产实践验证。微服务会增加网络失败、分布式事务、契约、部署、可观测和 on-call 成本。

## 决策

使用 Monorepo，运行时分为 Web、Admin、API、Worker 四个可独立部署进程。API 内部按领域模块组织，同一 PostgreSQL 实例作为主数据，但每个模块通过 application service/repository 拥有写入边界。异步副作用通过 Outbox + BullMQ。

## 后果

优点：首期交付快、事务清晰、调试和部署简单、重构边界成本低。缺点：需要纪律防止模块互相穿透；单体部署可能包含无关模块；数据库仍是共享故障域。

## 约束

- 控制器不能跨模块直接写表。
- 数据库模型共享不代表业务所有权共享。
- Worker 任务幂等。
- 新微服务必须有独立扩缩容、故障隔离、合规或团队自治证据，并新增 ADR。

## 备选

- 从第一天微服务：拒绝，当前收益不足以覆盖复杂度。
- 单一 Next 全栈应用：拒绝，Admin/API/Worker 的部署和安全边界不足。
- Serverless 函数全量：暂不选，长任务、连接、成本和本地一致性更复杂。
